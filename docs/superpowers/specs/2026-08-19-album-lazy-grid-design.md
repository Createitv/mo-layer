# 相册纵向懒加载与捏合缩放设计

日期：2026-08-19

## 背景

当前相册首页已经使用 `UICollectionView`、可复用单元格、缩略图预取和捏合手势，但仍有三个结构性问题：

1. `VaultHomeView` 通过 `@Query` 一次读取全部 `VaultItem`，随后在内存中反复筛选、计数和构建渲染状态。
2. 相册网格虽然按需创建单元格，但数据不是分页读取；媒体数量增加后，初次进入、筛选和状态更新都会扩大工作量。
3. 当前缩放只对可见单元格做临时变换，最终布局切换没有稳定的手势中心锚点，容易产生跳动。

本设计把相册改为类似 iPhone 照片图库的纵向连续浏览体验：没有“上一页/下一页”按钮，滚动到哪里就预取到哪里，并允许捏合改变图库密度。

## 目标

- 相册按时间倒序纵向连续滚动。
- 首批和后续批次都按需读取，不一次加载全部相册媒体。
- 在用户到达末尾前自动预取下一批，不要求点击加载按钮。
- 支持 `1 / 3 / 5 / 7` 列，首次默认 3 列并记住最后档位。
- 捏合缩放时保持双指中心对应的照片位置稳定。
- 图片和视频在高速滚动时不触发主线程原图解码或播放器创建。
- 保留现有筛选、收藏、Mo Layer、长按选择和滑动多选能力。
- 不改变现有加密存储与 CloudKit 数据格式。

## 非目标

- 不复制 Apple Photos 的日期聚类、年/月视图或机器学习搜索。
- 不在相册网格中自动播放视频。
- 不支持在单张预览内部继续上一张或下一张分页。
- 不在本次改动中重构音频、文档等非相册页面的视觉布局。
- 不在本次改动中修改 CloudKit schema。

## 已确认的产品行为

- 采用现有 `UICollectionView` 的增量升级方案，不改成纯 SwiftUI 网格，也不整体重写为新的 diffable 架构。
- 缩放对象是整个图库，不是单张照片内容。
- 缩放档位为 `1 / 3 / 5 / 7` 列；首次进入默认 3 列。
- 1 列仍是纵向图库中的大尺寸方形缩略图，不进入分页浏览。
- 点击照片或视频只打开当前项目，不再构建相邻项目列表，也不显示“上一页/下一页”。
- 关闭预览后恢复原来的滚动位置和列数。

## 架构

### 1. `AlbumMediaPagingController`

新增一个主线程可观察的分页控制器，专门管理相册当前作用域的数据。它拥有：

- 当前作用域：普通空间或 Mo Layer。
- 当前媒体筛选：全部、照片或视频。
- 是否仅显示收藏。
- 已加载的稳定有序 `VaultItem` 数组。
- 分页游标、`hasMore`、首次加载状态、追加加载状态和可重试错误。
- 当前请求代次，用于丢弃作用域切换后返回的过期结果。

控制器不负责图片解密、缩略图解码或 UICollectionView 布局。它只负责查询、去重、排序、分页状态与变更后的刷新。

### 2. `AlbumMediaPageQuery`

把 SwiftData 查询构造从视图中分离出来，形成可单元测试的查询策略：

- 只查询 `deletedAt == nil` 且类型为 `image`、`livePhoto` 或 `video` 的项目。
- 根据空间、媒体筛选和收藏状态生成对应谓词。
- 使用 `createdAt` 倒序、`id` 稳定排序。
- 使用 `(createdAt, id)` 作为游标边界，避免深页 `fetchOffset` 越来越慢，也避免同一创建时间的数据被漏掉或重复。
- 每页最多 200 条；多取 1 条用于判断是否还有下一页。

### 3. 首页数据边界

相册网格只消费分页控制器的 `items`，不再消费全量 `@Query` 的过滤结果。首页中仅为了显示数量、免费额度和分类角标的逻辑改为 `fetchCount` 或轻量聚合查询；不会为了一个数字物化全部相册对象。

非相册分类保留现有呈现逻辑，但其查询必须排除视觉媒体，避免相册项目通过另一条 `@Query` 再次全部进入内存。需要对全部项目执行的批量操作改为用户触发时按条件查询，而不是长期持有全量数组。

### 4. `AlbumZoomableMediaGrid`

保留现有 UIKit 网格桥接、单元格和手势入口，新增以下输入和回调：

- 离尾部的预取阈值回调。
- 首次加载、追加加载、无更多数据和追加失败状态。
- 离散列数绑定，而不是任意连续比例作为最终状态。
- 当前缩放锚点的稳定项目 ID 和相对位置。

追加新页时只插入新增索引，不执行整表 `reloadData()`。收藏、选择、同步状态等单项变化继续只重配受影响的可见单元格。

## 数据流

### 首次进入

1. 首页根据空间、媒体筛选和收藏状态构造作用域键。
2. 分页控制器取消旧任务、清空旧游标并读取第一页。
3. 网格显示第一页，并立即为可见区域和滚动方向前方的缩略图预取。
4. 第一页为空时才显示空状态；加载过程中不先显示错误的“没有内容”。

### 继续滚动

1. UICollectionView 根据当前列数估算两屏需要的项目数。
2. 当预取索引进入尾部两屏范围时调用 `loadNextPageIfNeeded()`。
3. 控制器防止重复请求，并把下一页稳定去重后追加。
4. 网格插入新增项目，保持当前 `contentOffset` 不变。
5. 如果请求失败，已加载内容保持可用；尾部提供轻量重试状态。

### 作用域变化

切换空间、全部/照片/视频或收藏时：

1. 增加请求代次并取消旧任务。
2. 清空旧分页状态和旧缩略图预取任务。
3. 读取新作用域第一页。
4. 默认回到新作用域顶部，但不修改用户保存的列数。

### 导入、删除、收藏和云同步

- 本地导入完成、删除完成、移动空间完成和远端同步合并完成后，显式通知分页控制器刷新当前作用域。
- 刷新时记录顶部可见项目 ID 与相对偏移；若该项目仍存在，刷新后恢复其视觉位置。
- 收藏筛选开启时，取消收藏可能导致当前项目消失；此时使用其后一项作为恢复锚点。
- 删除和同步不会让已发出的旧分页结果覆盖新的作用域状态。

## 捏合缩放

### 档位

- 支持 1、3、5、7 列。
- 全新安装或没有保存值时使用 3 列。
- 手势结束后保存最终列数；下次进入恢复该档位。

### 锚点算法

1. 手势开始时获取双指中心在 collection view 内容坐标中的位置。
2. 找到该点下方或距离该点最近的项目，记录项目 ID 及双指中心相对该项目中心的偏移比例。
3. 手势变化时只对可见单元格做 GPU 友好的临时缩放，避免每一帧对全部已加载项目重新布局。
4. 跨过相邻档位阈值或手势结束时提交目标列数并更新布局。
5. 布局后重新找到锚点项目，修正 `contentOffset`，让它回到双指中心附近。
6. 将偏移限制在合法滚动范围内，避免顶部和底部出现回弹式跳动。

追加分页数据不会改变现有项目顺序，因此不会破坏缩放锚点。捏合期间暂停低优先级预取；提交新档位后按照新的像素尺寸重新预取。

## 图片生命周期与缓存

- UICollectionView 单元格继续使用稳定项目 ID，复用时立即取消旧图片任务。
- 解密后使用 Image I/O 在后台直接生成目标像素尺寸的缩略图，不通过 `UIImage(data:)` 在主线程解码完整图片。
- 缓存键至少包含项目 ID、缩略图内容版本和像素尺寸档位，避免从 7 列切到 1 列时重复使用模糊图片。
- 内存缓存同时设置总成本上限和数量上限；收到内存警告后保留可见项目，清理其余解码图片。
- 快速反向滚动时取消已经离开预取窗口的任务。
- 解密路径、原始文件名和明文元数据不写入性能日志。

## 视频生命周期

- 网格只加载视频缩略图、时长和播放标记。
- 滚动或缩放过程中不创建 `AVPlayer`、不解密完整视频、不生成邻近播放器。
- 点击视频后才准备当前项目对应的临时解密资源和唯一播放器。
- 预览关闭、应用锁定或切到后台时暂停并释放播放器、时间观察者和不再需要的临时资源。
- 播放准备失败时显示当前项目的重试状态，不影响图库继续滚动。

## 单项预览

- 网格点击只把当前项目 ID 传给预览层。
- 预览层不接收全部分页数组，不预建前后项目，也不显示上一页或下一页按钮。
- 关闭预览时由网格自身保留滚动状态，不通过重新创建全部内容来恢复位置。
- 照片和 Live Photo 沿用当前单项展示能力；本次不新增单张照片内部的捏合缩放。

## 错误处理

- 首次查询失败：显示非破坏性错误状态与重试入口。
- 追加查询失败：保留已加载项目，只在尾部显示重试。
- 重复分页触发：同一作用域同一时间最多一个追加请求。
- 旧请求返回：请求代次不匹配时丢弃结果。
- 缩略图失败：显示现有占位图，可见时允许后续重试。
- 内存警告：取消屏幕外图片任务并清理非可见缓存，不清空当前分页元数据。

## 安全边界

- 不改变文件加密、密钥包装、CloudKit 私有数据库或落盘策略。
- 分页只读取已加密媒体的索引字段，不把明文元数据写回新的缓存文件。
- 内存中的解密缩略图保持有界，应用锁定和内存警告时主动清理。
- 不在日志中记录明文媒体路径、原始名称、解密数据或用户内容。
- 临时解密视频沿用现有受保护目录和清理规则，并在播放器释放后尽快删除。

## 测试

### 单元测试

- 查询作用域正确覆盖普通空间、Mo Layer、全部/照片/视频和收藏组合。
- 复合游标在相同 `createdAt` 下不漏项、不重复，并保持稳定顺序。
- 首次加载、追加、防重复请求、无更多数据、失败重试和旧请求丢弃。
- 导入、删除、取消收藏和同步刷新后的锚点恢复策略。
- `1 / 3 / 5 / 7` 档位吸附、默认 3 列和已保存档位恢复。
- 缩放前后锚点项目及相对位置误差在允许范围内。
- 缓存键包含尺寸和内容版本，内存警告清理屏幕外内容。
- 单项预览不接收或创建相邻项目集合。

### 构建与静态验证

- 使用 generic iOS Simulator destination 完成编译，不启动模拟器。
- 运行与分页、布局、缓存和预览策略相关的确定性单元测试。
- 检查 Main Thread Checker、并发隔离警告和任务取消路径。

### 真机验收

由用户在真实 iPhone 上完成以下操作：

- 使用包含大量照片和视频的图库，从顶部连续快速滑到底部。
- 在快速滚动中反复切换 1、3、5、7 列。
- 在列表中部捏合，确认手指中心照片不会明显跳位。
- 在加载下一页时继续滚动，确认没有整页闪烁、滚动回弹或长时间空白。
- 打开和关闭照片、视频，确认返回位置不变且不存在上一页/下一页界面。
- 连续打开多个视频后确认播放状态、内存和临时文件可以释放。

如果真机仍有明显卡顿，再使用 Instruments 的 Time Profiler、Hangs 和 Animation Hitches 采集真实设备数据；不把模拟器流畅度作为最终结论。

## 验收标准

- 相册不存在上一页或下一页按钮。
- 首次只读取一页相册数据，后续滚动自动追加。
- 同一项目不会因分页边界重复出现或遗漏。
- 追加数据不改变用户当前滚动位置。
- 缩放只落在 1、3、5、7 列，首次默认 3 列，并记住最后选择。
- 捏合中心项目在布局切换后保持在手指附近。
- 网格滚动和缩放期间不创建视频播放器或解码完整原图。
- 退出预览返回相同项目和相同列数。
- 现有筛选、收藏、空间切换和多选功能继续工作。
- 不新增明文落盘、敏感日志或 CloudKit schema 变更。

## 预计影响文件

- `privacy/MainViews.swift`：接入分页控制器、替换相册全量数组依赖、单项预览入口和状态刷新。
- `privacy/MediaGridViews.swift`：分页触发、增量插入、离散列数、缩放锚点和缓存窗口协调。
- `privacy/AlbumMediaPagingController.swift`：新增分页状态、查询、游标和刷新逻辑。
- `privacy/VaultStore.swift`：尺寸感知缩略图接口与受限缓存回收。
- `privacyTests/privacyTests.swift`：分页、缩放档位、锚点、缓存和单项预览策略测试。

实现阶段应尽量把新策略类型放入独立文件；不对与本功能无关的页面做格式化或重构。
